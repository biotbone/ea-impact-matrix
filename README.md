# ea-impact-matrix

A Claude Code skill that builds an Enterprise Architecture project impact matrix: it scores every proposed initiative on the same weighted dimensions, so a sequencing or funding decision can be defended in an architecture forum.

It exists to prevent one failure: a matrix where every initiative gets the same ratings looks like analysis and ranks nothing. The skill forces evidence-backed scores, an explicit prioritization lens chosen before scoring, cross-project dependencies, wave planning and an open-questions log.

## What you get

- `SKILL.md`: the method Claude follows (read sources, pick the lens, score 1 to 5 with evidence, add the money, find dependencies, plan waves, log what is missing).
- `scripts/build_impact_matrix.py`: generates the workbook from a JSON config, with fixed cell addresses so the summary and savings sheets stay wired.
- `EA_Impact_Matrix_TEMPLATE.xlsx`: a blank fill-in template with 8 project slots and one worked example.
- `examples/portfolio.example.json`: a starting config. All names, numbers and initiatives are fictional. It keeps one deliberate warning (a KPI with no baseline) so you can see `--check` work.
- `references/required-documents.md`: the documents the matrix is built from, what each one feeds in the workbook, what to look for and what to do when it is missing, plus an intake request you can send to the client. Generated by `--intake`.
- `references/standards-mapping.md`: how the method lines up with TOGAF and COBIT 2019.

The workbook has a scoring model with lens presets (balanced, run cost, deadline risk, delivery speed, security), a ranked portfolio summary, sequencing with entry conditions, a risk register with response and residual score, open questions, a savings case and a decision log. Dropdowns keep scores, statuses and decisions valid.

## Install

Copy this folder into your Claude Code skills directory, for example:

```bash
mkdir -p ~/.claude/skills
cp -r ea-impact-matrix ~/.claude/skills/
```

Claude loads it when you ask to build, review or prioritize a portfolio of initiatives.

## Use

```bash
pip install openpyxl

# blank template
python scripts/build_impact_matrix.py --template -o EA_Impact_Matrix_TEMPLATE.xlsx

# starting config to edit
python scripts/build_impact_matrix.py --dump-config portfolio.json

# list the documents the matrix needs, with an intake request
python scripts/build_impact_matrix.py --intake

# check a config against the method's rules, write nothing
python scripts/build_impact_matrix.py portfolio.json --check

# build from a completed config (runs the same check first)
python scripts/build_impact_matrix.py portfolio.json -o Impact_Matrix_v1.xlsx

# recalculate so formulas have cached values
soffice --headless --convert-to xlsx --outdir recalculated Impact_Matrix_v1.xlsx
```

Verify the recalculated file with `data_only=True` before trusting a rank.

## Tests

`python3 tests/run_tests.py` runs 42 checks against a fictional scenario with planted traps, an independent recomputation of the scores, and the script's own rules. See `tests/TEST_PLAN.md` and `tests/TEST_REPORT.md`.

## Standards

The method follows TOGAF and COBIT 2019 practice and uses their vocabulary where it helps (work package, transition architecture, residual risk, benefits owner). The new fields are optional and old configs still build. See `references/standards-mapping.md`.

## Data

Every example in this repository is invented. Do not commit client documents, names or figures to a fork. Keep real portfolio configs outside the repository.
